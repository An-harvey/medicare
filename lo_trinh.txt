## 2. XÁC THỰC & PHÂN QUYỀN

### 2.1 Cơ chế JWT
- Đăng nhập → Backend trả về `{ token, email, role }`
- Lưu token vào `localStorage` hoặc `httpOnly cookie`
- Mọi request cần xác thực → thêm header: `Authorization: Bearer <token>`

### 2.2 Các Role
| Role | Tiền tố route FE |
|------|-----------------|
| ADMIN | `/admin/*` |
| DOCTOR | `/doctor/*` |
| STAFF | `/staff/*` |
| PATIENT | `/patient/*` |

### 2.3 Axios Interceptor mẫu
```js
// src/api/axiosClient.js
import axios from 'axios';

const axiosClient = axios.create({
  baseURL: 'http://localhost:8080',
  headers: { 'Content-Type': 'application/json' },
});

axiosClient.interceptors.request.use((config) => {
  const token = localStorage.getItem('token');
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

axiosClient.interceptors.response.use(
  (res) => res.data,
  (err) => {
    if (err.response?.status === 401) {
      localStorage.clear();
      window.location.href = '/login';
    }
    return Promise.reject(err.response?.data || err.message);
  }
);

export default axiosClient;
```

### 5.1 AUTH (`/api/auth`) — Không cần token

#### POST `/api/auth/login`
**Request:**
```json
{ "email": "string", "password": "string" }
```
**Response `200`:**
```json
{ "token": "eyJhbGci...", "email": "user@gmail.com", "role": "PATIENT" }
```
> Lưu `token` và `role` vào store. Dùng `role` để redirect đúng dashboard.

#### POST `/api/auth/register`
**Request:**
```json
{
  "email": "string",
  "password": "string",
  "fullName": "string",
  "phone": "string (10 số)",
  "cccd": "string (12 số)"
}
```
**Response `201`:** `"Đăng ký thành công"` (plain string)

## 6. XỬ LÝ LỖI HTTP

| HTTP Code | Ý nghĩa | Xử lý FE |
|-----------|---------|---------|
| `200` | OK | Hiển thị data |
| `201` | Created | Thông báo tạo thành công |
| `400` | Bad Request | Hiển thị message lỗi từ response |
| `401` | Unauthorized | Token hết hạn → redirect `/login` |
| `403` | Forbidden | Không có quyền → hiển thị trang 403 |
| `404` | Not Found | Không tìm thấy tài nguyên |
| `500` | Server Error | Thông báo lỗi hệ thống |

**Cấu trúc lỗi từ Spring Boot:**
```json
{
  "timestamp": "2026-06-10T08:00:00",
  "status": 400,
  "error": "Bad Request",
  "message": "Email đã tồn tại trong hệ thống",
  "path": "/api/auth/register"
}
```

## 7. PHÂN TRANG (PAGINATION)

Các API có phân trang trả về cấu trúc `Page<T>` của Spring:

```json
{
  "content": [...],
  "pageable": { "pageNumber": 0, "pageSize": 10 },
  "totalElements": 150,
  "totalPages": 15,
  "last": false,
  "first": true,
  "numberOfElements": 10,
  "empty": false
}
```

**Ant Design Table config:**
```js
const [pagination, setPagination] = useState({ current: 1, pageSize: 10, total: 0 });

const res = await adminApi.getUsers({ page: pagination.current - 1, size: pagination.pageSize });
setPagination(prev => ({ ...prev, total: res.totalElements }));

// Trong Table:
<Table pagination={{ ...pagination, onChange: (page) => setPagination(prev => ({...prev, current: page})) }} />
```

## 11. LƯU Ý QUAN TRỌNG

### Format dữ liệu
- **Date:** gửi và nhận dạng `"yyyy-MM-dd"` (VD: `"2026-06-10"`)
- **Time:** dạng `"HH:mm:ss"` (VD: `"08:00:00"`)
- **UUID:** chuỗi 36 ký tự dạng `"xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"`
- **Enum:** gửi đúng chính xác theo string (VD: `"PENDING"`, không phải `"pending"`)

### Upload ảnh
- Endpoint nhận ảnh dùng `multipart/form-data`
- Field JSON data phải là **string** (`JSON.stringify(obj)`), không phải object
- Field file dùng tên đúng: `avatarFile`
- Ảnh trả về là `imageUrl` (tên file), hiển thị bằng: `http://localhost:8080/api/images/{imageUrl}`

### Token
- Token không có thời hạn cụ thể từ code → kiểm tra thực tế khi test
- Khi nhận 401 → xóa token, redirect `/login`
- Không gửi `patientId`/`createdById` trong body — backend tự lấy từ token

### Phân quyền route FE
```jsx
// ProtectedRoute.jsx
const ProtectedRoute = ({ allowedRole }) => {
  const { token, role } = useAuthStore();
  if (!token) return <Navigate to="/login" />;
  if (role !== allowedRole) return <Navigate to="/unauthorized" />;
  return <Outlet />;
};
```

### CORS
- Backend đã cấu hình CORS — FE chạy `localhost:3000` hay `localhost:5173` đều được
- Nếu gặp lỗi CORS: kiểm tra lại `CorsConfig.java` và thêm origin của FE

```js
updateProfile: (dto, avatarFile) => {

  });
```

```
[Bước 5] Nhập triệu chứng

    → Response 201: AppointmentResponseDTO

```

## 17. CÁCH LẤY VÀ HIỂN THỊ ẢNH ĐẠI DIỆN (AVATAR)

### Cơ chế hoạt động

Backend lưu ảnh vào thư mục `uploads/images/` trên server. Field `imageUrl` trong DB **chỉ lưu tên file** (ví dụ: `a1b2c3d4-uuid.jpg`), **không phải URL đầy đủ**.

> ⚠️ Ngoại lệ: Nếu bác sĩ upload ảnh qua endpoint `PUT /api/doctor/profile`, backend lưu URL đầy đủ (`http://localhost:8080/api/images/...`) vào DB thay vì chỉ tên file. FE cần xử lý cả 2 trường hợp.

### Quy tắc hiển thị ảnh

```js
// src/utils/formatters.js
const BASE_URL = 'http://localhost:8080';

export function getAvatarUrl(imageUrl) {
  if (!imageUrl) return '/default-avatar.png';  // ảnh mặc định nếu null

  // Nếu đã là URL đầy đủ (bác sĩ upload qua /api/doctor/profile)
  if (imageUrl.startsWith('http')) return imageUrl;

  // Nếu chỉ là tên file (patient, admin upload)
  return `${BASE_URL}/api/images/${imageUrl}`;
}
```

```jsx
// Dùng trong component
<img src={getAvatarUrl(doctor.imageUrl)} alt={doctor.fullName} />
<img src={getAvatarUrl(patient.imageUrl)} alt={patient.fullName} />
```

### imageUrl xuất hiện ở những DTO nào

| DTO | Field | Ai có ảnh |
|-----|-------|-----------|
| `DoctorResponseDTO` | `imageUrl` | Bác sĩ (public list) |
| `DoctorDetailResponseDTO` | `imageUrl` | Bác sĩ (chi tiết) |
| `PatientProfileResponseDTO` | `imageUrl` | Bệnh nhân |

### Upload ảnh — tóm tắt nhanh

| Role | Endpoint | Field JSON | Field file |
|------|----------|-----------|-----------|
| Patient | `POST /api/patient/profile` | `data` | `avatarFile` |
| Doctor | `PUT /api/doctor/profile` | `dto` | `avatarFile` |

```js
// Mẫu dùng chung cho cả Patient và Doctor (chỉ khác tên field JSON)
function buildAvatarFormData(jsonData, avatarFile, jsonFieldName = 'data') {
  const formData = new FormData();
  formData.append(jsonFieldName, JSON.stringify(jsonData));
  if (avatarFile) formData.append('avatarFile', avatarFile);
  return formData;
}

// Patient
const fd = buildAvatarFormData(profileData, file, 'data');
await axiosClient.post('/api/patient/profile', fd, {
  headers: { 'Content-Type': 'multipart/form-data' }
});

// Doctor
const fd = buildAvatarFormData(profileData, file, 'dto');
await axiosClient.put('/api/doctor/profile', fd, {
  headers: { 'Content-Type': 'multipart/form-data' }
});
```

### Giới hạn file upload
- Định dạng cho phép: **JPG, JPEG, PNG**
- Kích thước tối đa: **5MB mỗi file**
- FE nên validate trước khi gửi để tránh lỗi 400 từ server

```js
function validateAvatarFile(file) {
  const allowedTypes = ['image/jpeg', 'image/jpg', 'image/png'];
  if (!allowedTypes.includes(file.type)) {
    return 'Chỉ chấp nhận file JPG, JPEG hoặc PNG';
  }
  if (file.size > 5 * 1024 * 1024) {
    return 'File không được vượt quá 5MB';
  }
  return null; // hợp lệ
}
```

### ⚠️ ĐÍNH CHÍNH QUAN TRỌNG — AppointmentStatus

Tài liệu cũ thiếu 2 trạng thái. Đây là danh sách **đầy đủ và đúng**:

```js
export const APPOINTMENT_STATUS = {
  PENDING:     { label: 'Chờ xác nhận',  color: 'gold' },       // Bệnh nhân tự đặt online
  CONFIRMED:   { label: 'Đã xác nhận',   color: 'blue' },       // Staff đặt hộ HOẶC staff xác nhận
  CHECK_IN:    { label: 'Đã check-in',   color: 'cyan' },       // Bệnh nhân đến quầy, staff check-in
  IN_PROGRESS: { label: 'Đang khám',     color: 'processing' }, // Bác sĩ bắt đầu khám
  COMPLETED:   { label: 'Hoàn tất',      color: 'green' },      // Bác sĩ kết thúc, đã có bệnh án
  CANCELLED:   { label: 'Đã hủy',        color: 'red' },        // Bệnh nhân hoặc hệ thống hủy
  NO_SHOW:     { label: 'Vắng mặt',      color: 'default' },    // Không đến không báo
};
```

**Luồng chuyển trạng thái hợp lệ:**
```
PENDING → CONFIRMED (staff xác nhận)
PENDING/CONFIRMED → CHECK_IN (staff check-in khi bệnh nhân đến)
CHECK_IN → IN_PROGRESS (bác sĩ bắt đầu khám)
IN_PROGRESS → COMPLETED (bác sĩ kết thúc + tạo bệnh án)
PENDING/CONFIRMED → CANCELLED (bệnh nhân hủy, phải trước 2 tiếng)
PENDING/CONFIRMED → NO_SHOW (staff đánh dấu vắng)
```

> Khi staff đặt hộ bệnh nhân tại quầy → status mặc định là **CONFIRMED** (không phải PENDING).
> Khi bệnh nhân tự đặt online → status mặc định là **PENDING**.

## 19. API BỔ SUNG CẦN THIẾT CHO FE

> Các API hiện tại chưa có trong backend nhưng FE cần để thao tác dễ dàng. Liệt kê để BE bổ sung.

### 19.1 Tìm bệnh nhân theo CCCD (Staff cần khi đặt lịch tại quầy)

**Vấn đề:** Staff đặt lịch tại quầy cần `patientId` (UUID) để gọi `POST /api/staff/appointments/patient/{patientId}`. Nhưng bệnh nhân chỉ cung cấp CCCD. Hiện tại không có API nào tra UUID từ CCCD.

**Đề xuất thêm:**
```
GET /api/staff/patients/search?cccd={cccd}
```
**Response:** `PatientProfileResponseDTO` (hoặc chỉ `{ patientId, fullName, phone }`)

**Workaround hiện tại:** Dùng `GET /api/staff/appointments?cccd={cccd}` → lấy `patientName` nhưng **không có `patientId`** → chưa đủ để đặt lịch hộ. **Cần BE bổ sung API này.**

---

### 19.2 Danh sách bệnh lý cho bác sĩ kê khi tạo bệnh án

**Vấn đề:** Khi bác sĩ tạo bệnh án cần chọn `diseaseId`, nhưng hiện tại `/api/admin/diseases` chỉ cho ADMIN gọi.

**Đề xuất thêm:**
```
GET /api/doctor/diseases?keyword={keyword}
```
Hoặc mở rộng quyền endpoint hiện tại:
```
GET /api/public/diseases?keyword={keyword}&page=0&size=20
```

**Workaround:** Gọi thẳng `/api/admin/diseases` nhưng phải dùng token Admin — **không an toàn**. Cần BE bổ sung.

---

### 19.3 Danh sách thuốc cho bác sĩ kê đơn

Tương tự trên, `/api/admin/medicines` chỉ cho ADMIN.

**Đề xuất thêm:**
```
GET /api/doctor/medicines?keyword={keyword}
```
hoặc:
```
GET /api/public/medicines?keyword={keyword}
```

---

### 19.4 Danh sách bệnh nhân cho Staff (khi đặt lịch hộ)

**Đề xuất thêm:**
```
GET /api/staff/patients?keyword={cccd_or_name}&page=0&size=10
```
**Response:** `Page<PatientProfileResponseDTO>`

---

### 19.5 Xem chi tiết doctor public (trang profile bác sĩ)

Hiện tại `/api/public/doctors` trả về list rút gọn. Khi user click vào 1 bác sĩ để xem chi tiết (tiểu sử, thế mạnh) cần thêm:

**Đề xuất thêm:**
```
GET /api/public/doctors/{doctorId}
```
**Response:** `DoctorDetailResponseDTO`

---

### 19.6 Bác sĩ xem danh sách bệnh nhân của mình

**Đề xuất thêm:**
```
GET /api/doctor/patients
```
Trả về danh sách bệnh nhân đã từng khám với bác sĩ này, kèm thông tin cơ bản.

```
    │                    │           GET /api/doctor/appointments/upcoming
    │                    │                           │
    │                    │        4. Bắt đầu khám   │
    │                    │           PUT /api/doctor/appointments/{id}/status
    │                    │           ?status=IN_PROGRESS
    │                    │                           │
    │                    │        5. (Tùy chọn) Xem hồ sơ BN
    │                    │           GET /api/doctor/patients/{patientId}/profile
    │                    │                           │
    │                    │        6. Tạo bệnh án    │
    │                    │           POST /api/doctor/medical-records
    │                    │           → Tự động COMPLETED
    │                    │                           │
    │  Nhận notification │                           │
    │◄─────────────────────────────────────────────│
```

### BƯỚC 1 — STAFF: Tìm phiếu đặt lịch của bệnh nhân khi đến quầy

**Mục đích:** Bệnh nhân đến quầy, staff tra cứu lịch hẹn theo CCCD hoặc ngày.

**API:**
```
GET /api/staff/appointments?cccd={cccd}
hoặc
GET /api/staff/appointments?date={yyyy-MM-dd}
```

> ⚠️ Phải truyền ít nhất 1 trong 2. Nếu truyền cả 2 thì **`cccd` được ưu tiên**, `date` bị bỏ qua.

**Ví dụ thực tế:**
```
GET /api/staff/appointments?cccd=001099012345
```

**Response `200`:** `AppointmentResponseDTO[]`
```json
[
  {
    "appointmentId": "a1b2c3d4-...",
    "patientName": "Nguyễn Văn A",
    "doctorName": "BS. Trần Văn Minh",
    "workDate": "2026-06-20",
    "startTime": "08:00:00",
    "symptoms": "Đau ngực, khó thở khi gắng sức",
    "status": "PENDING",
    "cancelReason": null
  }
]
```

> Staff dùng `appointmentId` từ response này cho Bước 2.
> Lọc hiển thị những appointment có `status = PENDING` hoặc `CONFIRMED` để check-in.
> Không check-in cho appointment `CANCELLED`, `COMPLETED`, `NO_SHOW`.

### BƯỚC 2 — STAFF: Check-in khi bệnh nhân đến

**Mục đích:** Xác nhận bệnh nhân đã đến phòng khám, chuyển trạng thái sang `CHECK_IN`.

**API:**
```
PUT /api/staff/appointments/{appointmentId}/status?status=CHECK_IN
```

| Param | Kiểu | Bắt buộc | Ghi chú |
|-------|------|----------|---------|
| `appointmentId` (path) | UUID | ✅ | Lấy từ kết quả Bước 1 |
| `status` (query) | string | ✅ | Truyền cố định `CHECK_IN` |

**Không có request body.**

**Ví dụ:**
```
PUT /api/staff/appointments/a1b2c3d4-.../status?status=CHECK_IN
```

**Response `200`:** plain string `"Cập nhật trạng thái cuộc hẹn thành công."`

**Kết quả sau bước này:**
- Appointment status → `CHECK_IN`
- Bệnh nhân nhận notification: *"Bạn đã check-in thành công. Vui lòng chờ đến lượt."*
- Phiếu lúc này hiển thị đúng tên, giờ, và bác sĩ phụ trách

### BƯỚC 6 — BÁC SĨ: Tạo bệnh án + kê đơn thuốc (quan trọng nhất)

**Mục đích:** Sau khi khám xong, bác sĩ nhập chẩn đoán, chọn bệnh lý, kê đơn thuốc.

#### 6c. Tạo bệnh án — API chính

**API:**
```
POST /api/doctor/medical-records
Content-Type: application/json
Authorization: Bearer {token bác sĩ}
```

**Request body — đầy đủ từng field:**

| Field | Kiểu | Bắt buộc | Ghi chú |
|-------|------|----------|---------|
| `appointmentId` | UUID | ✅ | Lấy từ `appointmentId` ở Bước 3 |
| `clinicalDiagnosis` | string | ✅ | Chẩn đoán lâm sàng |
| `doctorNotes` | string | ❌ | Ghi chú thêm, lời dặn dò bệnh nhân |
| `diseases` | array | ✅ | Tối thiểu 1 phần tử, **bắt buộc có ít nhất 1 bệnh `isPrimary: true`** |
| `diseases[].diseaseId` | integer | ✅ | `id` từ danh mục bệnh lý |
| `diseases[].isPrimary` | boolean | ✅ | `true` = bệnh chính, `false` = bệnh kèm theo |
| `medicines` | array \| null | ❌ | `null` hoặc `[]` nếu không kê đơn |
| `medicines[].medicineId` | integer | ✅ | `id` từ danh mục thuốc |
| `medicines[].quantity` | integer | ✅ | Số lượng (đơn vị theo `unit` của thuốc) |
| `medicines[].dosageInstructions` | string | ✅ | Cách dùng: liều lượng, thời điểm uống |

**Ví dụ request đầy đủ:**
```json
{
  "appointmentId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "clinicalDiagnosis": "Tăng huyết áp giai đoạn 1 kèm rối loạn lipid máu",
  "doctorNotes": "Hạn chế muối dưới 5g/ngày, tập thể dục nhẹ 30 phút/ngày, tái khám sau 4 tuần",
  "diseases": [
    { "diseaseId": 5, "isPrimary": true },
    { "diseaseId": 12, "isPrimary": false }
  ],
  "medicines": [
    {
      "medicineId": 3,
      "quantity": 30,
      "dosageInstructions": "1 viên/ngày sau ăn sáng"
    },
    {
      "medicineId": 7,
      "quantity": 30,
      "dosageInstructions": "1 viên/ngày sau ăn tối"
    }
  ]
}
```

**Ví dụ không kê đơn thuốc:**
```json
{
  "appointmentId": "a1b2c3d4-...",
  "clinicalDiagnosis": "Cảm cúm thông thường",
  "doctorNotes": "Nghỉ ngơi, uống nhiều nước, tự khỏi sau 5-7 ngày",
  "diseases": [
    { "diseaseId": 8, "isPrimary": true }
  ],
  "medicines": null
}
```

**Lỗi thường gặp:**
| HTTP | Nguyên nhân | Hiển thị cho user |
|------|------------|-------------------|
| `400` | Appointment đã có bệnh án (COMPLETED) | "Ca khám này đã được lập bệnh án trước đó" |
| `400` | Không có bệnh nào là `isPrimary: true` | "Bắt buộc phải chỉ định ít nhất một bệnh chính" |
| `404` | `diseaseId` không tồn tại | "Mã bệnh lý không hợp lệ" |
| `404` | `medicineId` không tồn tại | "Thuốc không có trong danh mục" |
| `404` | `appointmentId` không tồn tại | "Không tìm thấy cuộc hẹn" |

**Response `201`:** `MedicalRecordResponseDTO`
```json
{
  "medicalRecordId": "uuid-benh-an-moi",
  "appointmentId": "a1b2c3d4-...",
  "patientName": "Nguyễn Văn A",
  "doctorName": "BS. Trần Văn Minh",
  "clinicalDiagnosis": "Tăng huyết áp giai đoạn 1 kèm rối loạn lipid máu",
  "doctorNotes": "Hạn chế muối dưới 5g/ngày...",
  "diagnosedDiseases": [
    "Cao huyết áp (Chính)",
    "Rối loạn lipid máu"
  ]
}
```

**Điều xảy ra tự động sau khi tạo bệnh án thành công:**
1. Appointment status → **`COMPLETED`** (tự động, không cần gọi thêm API)
2. Nếu có thuốc → Tạo `Prescription` với `dispenseStatus = PENDING` (chờ staff cấp phát)
3. Bệnh nhân nhận notification: *"Cuộc hẹn với BS. Trần Văn Minh đã hoàn tất. Vui lòng xem bệnh án."*

### Tóm tắt nhanh — Ai gọi API nào theo thứ tự

```
STAFF
  [1] GET  /api/staff/appointments?cccd={cccd}
           → Lấy appointmentId, kiểm tra status
  [2] PUT  /api/staff/appointments/{appointmentId}/status?status=CHECK_IN
           → Check-in, bệnh nhân nhận notification

BÁC SĨ
  [3] GET  /api/doctor/appointments/upcoming
           → Xem danh sách chờ khám (PENDING + CHECK_IN)
  [4] PUT  /api/doctor/appointments/{appointmentId}/status?status=IN_PROGRESS
           → Bắt đầu khám (chỉ được khi status = CHECK_IN)
  [5] GET  /api/doctor/patients/{patientId}/profile          ← tùy chọn
           → Xem tiền sử, dị ứng bệnh nhân
  [6] POST /api/doctor/medical-records
           → Tạo bệnh án + kê đơn thuốc
           → Tự động: appointment → COMPLETED, gửi notification cho BN

BỆNH NHÂN
  [7] GET  /api/patient/medical-records
           → Xem danh sách bệnh án
  [8] GET  /api/patient/medical-records/{medicalRecordId}
           → Xem chi tiết bệnh án + đơn thuốc đầy đủ
```

### Lưu ý cho FE khi implement màn hình bác sĩ

**Màn hình danh sách chờ khám (Bước 3):**
- Sắp xếp: `CHECK_IN` lên trên, `PENDING` xuống dưới
- Mỗi row hiển thị: tên BN, giờ hẹn, triệu chứng, status badge
- Nút "Bắt đầu khám" chỉ enable khi `status = CHECK_IN`
- Nút "Xem hồ sơ" → cần `patientId` — **BE cần bổ sung `patientId` vào `AppointmentResponseDTO`**

**Màn hình tạo bệnh án (Bước 6):**
- Ô tìm kiếm bệnh lý: debounce 300ms, gọi API tìm kiếm theo keyword
- Có thể chọn nhiều bệnh lý, cần chỉ định 1 bệnh chính (radio button hoặc checkbox đặc biệt)
- Ô tìm kiếm thuốc: tương tự, chọn xong nhập số lượng + hướng dẫn sử dụng
- Submit → gọi `POST /api/doctor/medical-records`
- Sau khi thành công → redirect về danh sách chờ khám (appointment đó biến mất khỏi danh sách vì đã COMPLETED)

**Xử lý `patientId` trong AppointmentResponseDTO (vấn đề hiện tại):**

Hiện tại `AppointmentResponseDTO` chỉ có `patientName` (string), không có `patientId` (UUID). Backend cần sửa:

```java
// AppointmentResponseDTO.java — cần thêm field này
private UUID patientId;  // ← BE bổ sung

// AppointmentMapper.java — cần thêm mapping
@Mapping(source = "patient.patientId", target = "patientId")  // ← BE bổ sung
```

FE cần chờ BE bổ sung field này mới có thể implement Bước 5 hoàn chỉnh.

## 23. HỆ THỐNG THÔNG BÁO (NOTIFICATIONS) — TÀI LIỆU ĐẦY ĐỦ CHO FRONTEND

---

### Tổng quan cơ chế

- Notification được tạo **tự động từ phía backend** khi có sự kiện xảy ra — FE không cần gọi API tạo.
- Mỗi notification gắn với **1 user cụ thể** (theo `userId` từ token).
- FE chỉ cần làm 3 việc: **lấy danh sách**, **lấy số chưa đọc**, **đánh dấu đã đọc**.
- Áp dụng cho **tất cả role**: PATIENT, DOCTOR, STAFF, ADMIN.

---

### Các sự kiện backend tự tạo notification

| # | Sự kiện | Ai nhận | Nội dung message | `link` |
|---|---------|---------|-----------------|--------|
| 1 | Bệnh nhân / Staff đặt lịch thành công | Bệnh nhân | `"Lịch hẹn của bạn với BS. {tên} vào lúc {giờ} ngày {ngày} đã được tạo và đang chờ xác nhận."` | `/patient/appointments` |
| 2 | Staff đặt lịch hộ tại quầy | Bệnh nhân | `"Lịch hẹn của bạn với BS. {tên} vào lúc {giờ} ngày {ngày} đã được tạo và đã được xác nhận."` | `/patient/appointments` |
| 3 | Staff xác nhận lịch (`CONFIRMED`) | Bệnh nhân | `"Lịch hẹn của bạn đã được xác nhận."` | `/patient/appointments` |
| 4 | Staff check-in (`CHECK_IN`) | Bệnh nhân | `"Bạn đã check-in thành công. Vui lòng chờ đến lượt."` | `null` |
| 5 | Bệnh nhân hủy lịch (`CANCELLED`) | Bệnh nhân | `"Lịch hẹn của bạn vào lúc {giờ} ngày {ngày} đã bị hủy. Lý do: {reason}"` | `/patient/appointments` |
| 6 | Bác sĩ tạo bệnh án xong (`COMPLETED`) | Bệnh nhân | `"Cuộc hẹn với BS. {tên} đã hoàn tất. Vui lòng xem bệnh án."` | `/patient/medical-records` |

> Hiện tại **chỉ bệnh nhân nhận notification**. Doctor/Staff chưa có notification từ hệ thống.

---

### 3 API Notification

---

#### GET `/api/notifications` — Lấy toàn bộ thông báo của tôi

- Yêu cầu token (bất kỳ role nào)
- Trả về **tất cả** thông báo, sắp xếp **mới nhất trước** (`ORDER BY createdAt DESC`)
- Không có phân trang

**Request:** Không có body, không có query param.

**Response `200`:** `NotificationResponseDTO[]`
```json
[
  {
    "id": "uuid-thong-bao-1",
    "message": "Cuộc hẹn với BS. Trần Văn Minh đã hoàn tất. Vui lòng xem bệnh án.",
    "isRead": false,
    "createdAt": "2026-06-20T10:45:00",
    "link": "/patient/medical-records"
  },
  {
    "id": "uuid-thong-bao-2",
    "message": "Bạn đã check-in thành công. Vui lòng chờ đến lượt.",
    "isRead": true,
    "createdAt": "2026-06-20T08:05:00",
    "link": null
  },
  {
    "id": "uuid-thong-bao-3",
    "message": "Lịch hẹn của bạn với BS. Trần Văn Minh vào lúc 08:00:00 ngày 20/06/2026 đã được tạo và đang chờ xác nhận.",
    "isRead": true,
    "createdAt": "2026-06-18T14:30:00",
    "link": "/patient/appointments"
  }
]
```

**Các field:**
| Field | Kiểu | Mô tả |
|-------|------|-------|
| `id` | UUID | ID thông báo — dùng để đánh dấu đã đọc |
| `message` | string | Nội dung thông báo |
| `isRead` | boolean | `false` = chưa đọc, `true` = đã đọc |
| `createdAt` | `LocalDateTime` | Thời điểm tạo — format `"yyyy-MM-ddTHH:mm:ss"` |
| `link` | string \| null | Route để navigate khi click. Có thể `null` |

---

#### GET `/api/notifications/unread-count` — Số thông báo chưa đọc

- Dùng để hiển thị **badge số** trên icon chuông
- Gọi định kỳ để cập nhật real-time (polling)

**Request:** Không có gì.

**Response `200`:** số nguyên (`long`) — plain number, **không phải JSON object**
```
3
```

> Axios trả về `res.data` = `3` (number). Xử lý trực tiếp, không cần parse thêm.

---

#### PUT `/api/notifications/{id}/read` — Đánh dấu đã đọc

| Param | Kiểu | Bắt buộc | Ghi chú |
|-------|------|----------|---------|
| `{id}` (path) | UUID | ✅ | `id` của notification |

**Không có request body.**

**Lỗi thường gặp:**
- `404` — notification không tồn tại
- `403` — đánh dấu thông báo của người khác

**Response `204`:** No Content

### API function mẫu

```js
// src/api/notificationApi.js
import axiosClient from './axiosClient';

export const notificationApi = {
  // Lấy tất cả thông báo
  getAll: () => axiosClient.get('/api/notifications'),

  // Lấy số chưa đọc — trả về number
  getUnreadCount: () => axiosClient.get('/api/notifications/unread-count'),

  // Đánh dấu 1 thông báo đã đọc
  markAsRead: (id) => axiosClient.put(`/api/notifications/${id}/read`),
};
```

### Implement NotificationBell component

```jsx
// src/components/common/NotificationBell.jsx
import { useEffect, useState } from 'react';
import { Badge, Dropdown, List, Button } from 'antd';
import { BellOutlined } from '@ant-design/icons';
import { notificationApi } from '../../api/notificationApi';
import { useNavigate } from 'react-router-dom';
import dayjs from 'dayjs';
import relativeTime from 'dayjs/plugin/relativeTime';
import 'dayjs/locale/vi';

dayjs.extend(relativeTime);
dayjs.locale('vi');

export default function NotificationBell() {
  const navigate = useNavigate();
  const [notifications, setNotifications] = useState([]);
  const [unreadCount, setUnreadCount]     = useState(0);
  const [open, setOpen]                   = useState(false);
  const [loading, setLoading]             = useState(false);

  // Polling số chưa đọc mỗi 30 giây
  useEffect(() => {
    const fetchCount = async () => {
      try {
        const count = await notificationApi.getUnreadCount();
        setUnreadCount(count);
      } catch {}
    };
    fetchCount();
    const interval = setInterval(fetchCount, 30000);
    return () => clearInterval(interval);
  }, []);

  // Khi mở dropdown — fetch danh sách
  const handleOpenChange = async (isOpen) => {
    setOpen(isOpen);
    if (isOpen) {
      setLoading(true);
      try {
        const data = await notificationApi.getAll();
        setNotifications(data);
      } finally {
        setLoading(false);
      }
    }
  };

  // Click vào 1 thông báo
  const handleClick = async (notification) => {
    // Đánh dấu đã đọc nếu chưa đọc
    if (!notification.isRead) {
      await notificationApi.markAsRead(notification.id);
      setNotifications(prev =>
        prev.map(n => n.id === notification.id ? { ...n, isRead: true } : n)
      );
      setUnreadCount(prev => Math.max(0, prev - 1));
    }
    // Navigate nếu có link
    if (notification.link) {
      navigate(notification.link);
      setOpen(false);
    }
  };

  const dropdownContent = (
    <div style={{ width: 380, maxHeight: 480, overflowY: 'auto' }}>
      <div style={{ padding: '8px 16px', fontWeight: 600, borderBottom: '1px solid #f0f0f0' }}>
        Thông báo {unreadCount > 0 && <span style={{ color: '#ff4d4f' }}>({unreadCount} chưa đọc)</span>}
      </div>
      {loading ? (
        <div style={{ padding: 16, textAlign: 'center' }}>Đang tải...</div>
      ) : notifications.length === 0 ? (
        <div style={{ padding: 16, textAlign: 'center', color: '#999' }}>Không có thông báo</div>
      ) : (
        <List
          dataSource={notifications}
          renderItem={(item) => (
            <List.Item
              onClick={() => handleClick(item)}
              style={{
                padding: '10px 16px',
                cursor: item.link ? 'pointer' : 'default',
                background: item.isRead ? '#fff' : '#e6f4ff',  // xanh nhạt = chưa đọc
                borderBottom: '1px solid #f5f5f5',
              }}
            >
              <div style={{ width: '100%' }}>
                <div style={{ fontSize: 13, color: item.isRead ? '#555' : '#000', fontWeight: item.isRead ? 400 : 500 }}>
                  {item.message}
                </div>
                <div style={{ fontSize: 11, color: '#aaa', marginTop: 4 }}>
                  {dayjs(item.createdAt).fromNow()}
                </div>
              </div>
            </List.Item>
          )}
        />
      )}
    </div>
  );

  return (
    <Dropdown
      overlay={dropdownContent}
      trigger={['click']}
      open={open}
      onOpenChange={handleOpenChange}
      placement="bottomRight"
    >
      <Badge count={unreadCount} size="small" offset={[-2, 2]}>
        <Button
          type="text"
          icon={<BellOutlined style={{ fontSize: 20 }} />}
          style={{ display: 'flex', alignItems: 'center' }}
        />
      </Badge>
    </Dropdown>
  );
}
```

### Format thời gian `createdAt`

Backend trả về dạng `"2026-06-20T10:45:00"` (LocalDateTime, không có timezone).

```js
// Hiển thị dạng "vừa xong", "5 phút trước", "2 giờ trước"
import dayjs from 'dayjs';
import relativeTime from 'dayjs/plugin/relativeTime';
import 'dayjs/locale/vi';
dayjs.extend(relativeTime);
dayjs.locale('vi');

dayjs('2026-06-20T10:45:00').fromNow()  // → "2 giờ trước"

// Hoặc hiển thị đầy đủ
dayjs('2026-06-20T10:45:00').format('HH:mm DD/MM/YYYY')  // → "10:45 20/06/2026"
```

### Lưu ý quan trọng

**1. `link` có thể là `null`**
```js
// Luôn kiểm tra trước khi navigate
if (notification.link) navigate(notification.link);
```

**2. `isRead` trong JSON là `isRead` (camelCase)**
```js
// Axios/JSON trả về đúng camelCase
notification.isRead  // ✅ đúng
notification.is_read // ❌ sai
```

**3. Không có API "đánh dấu tất cả đã đọc"**
Backend chưa có endpoint này. Nếu FE muốn "Mark all as read" cần gọi loop từng cái:
```js
// Workaround khi chưa có bulk API
const markAllAsRead = async () => {
  const unread = notifications.filter(n => !n.isRead);
  await Promise.all(unread.map(n => notificationApi.markAsRead(n.id)));
  setNotifications(prev => prev.map(n => ({ ...n, isRead: true })));
  setUnreadCount(0);
};
```
> Đề xuất BE bổ sung: `PUT /api/notifications/read-all`

**4. Không có WebSocket/SSE — dùng polling**
Hệ thống hiện tại không có real-time push. Dùng `setInterval` polling `/unread-count` mỗi 30 giây là đủ cho usecase phòng khám.

**5. Notification chỉ bệnh nhân nhận**
Hiện tại backend chỉ gửi notification cho bệnh nhân. Doctor/Staff chưa có. FE nên render `NotificationBell` cho tất cả role nhưng Doctor/Staff sẽ thấy danh sách rỗng — không lỗi.
